# EFZ 终端仪表盘

[English](../../tui.md) · [Русский](../ru/tui.md) · [Español](../es/tui.md) · **简体中文** · [所有语言](../README.md)

可选的 Python/curses 查看器将滚动执行速率与覆盖图表、最后完成输入的十六进制和 ASCII
内容，以及已覆盖函数名显示在同一界面。它需要支持 curses 的 Python 3、交互式 UTF-8
终端和常规 OTP/Rebar 工具链。无需 Python 扩展包或 Web 服务器。

从仓库根目录执行：

```sh
rebar3 compile
python3 scripts/tui.py --demo --out _build/tui-demo-1
```

演示会对内置解析器插桩，运行 10,000 次变异，并故意包含人工目标异常。
它不会测试外部服务。每次使用新输出目录；已有结果绝不会被替换。

对于自己的目标，提供与 `efz:start/1` 接受的相同可信 Erlang 活动映射，
包括原始二进制种子和已准备好的产物映射：

```sh
python3 scripts/tui.py --config campaign.term --out _build/tui-run-1 \
  --code-path harness-ebin
python3 scripts/tui.py --attach _build/tui-run-1
```

可重复使用 `--code-path` 添加依赖或可选 Gleam 构建。
活动配置内的相对路径以仓库根目录为基准。启动器强制设置 `monitoring` 为 true，
`crash_dir` 为 OUTPUT/crashes；其他活动设置（包括持久化语料标识和策略）仍由调用方控制。
活动配置是可信的本地可执行配置，不是发现产物。此启动器目前使用常规单 VM 执行模式，
而非外部 `--supervised` CLI 协议。

## 屏幕与控制

- 左侧：滚动主执行速率（校准 + 变异）、累计覆盖、变异预算、校准次数、语料及发现统计。
- 右侧：最后完成输入的十六进制和 ASCII、阶段、父输入、结果及目标函数。
  输入预览最多 512 字节，截断时会标注。函数列表最多 64 项，仪表盘显示其中三项。
- 空格固定或解除固定输入及其结果和函数。图表继续更新。
- 上下键以每行 16 字节滚动输入预览。
- `q` 或 Ctrl-C 只关闭查看器。分离的活动继续运行；终端会打印 PID 和输出路径。
  可通过 `--attach OUTPUT` 重新连接。
- 支持终端尺寸变化。小于 90×26 时，面板会被调整尺寸提示替代。
  活动完成后，最终结果仍保留显示，直到关闭查看器。

后台桥接进程约每秒两次原子写入 snapshot.json，并在完成时写入 campaign.log 和常规
二进制 report.term。桥接失败会在启动它的查看器中报告；详情位于 campaign.log。
若要显式停止已分离的活动，可向打印出的桥接 PID 发送 SIGTERM。
这是进程取消，不保证生成完整报告；已持久化接纳的语料条目仍遵守 EFZ 的常规保证。
此首版仪表盘没有交互式重放、最小化或发现批注控制。

## 如实解读数据

界面输入来自最后一次**已完成**的执行，并非声称展示实时程序计数器。
对于源码插桩的 ETS 覆盖，精确到达的探针会根据所提供清单映射为函数。
如果缺少单次执行函数数据，未固定的面板会明确把回退数据标为**累计覆盖**。
没有函数清单的原生行覆盖和关闭覆盖的配置会显示函数数据不可用，而不会虚构调用栈。
尚未实现实时堆栈采样。

仅在已知清单探针总数时显示百分比。原生覆盖以行为单位标注；手动覆盖使用手动单位。
总数为零或不可用时，仅显示绝对数量。统计是累计的，而图表最多保留 120 个采样点。
速率依据快照时间内的执行数差值计算，不声称代表各目标延迟分布。

结果计数包含校准和主变异，不含额外运行时验证调用。`Returned value` 不代表语义成功。
只有明确的 `{efz_term_input_rejected, Reason}`、`rejected` 和 `{rejected, Reason}`
返回约定才被归类为编解码器或目标拒绝。其他返回错误仍属于返回值。
异常不会自动归类为实际缺陷：预期的解析器 throw 仍需合适的测试驱动契约或人工审查。
EFZ 旧的 `rejections` 计数还包含覆盖等价执行，此处不会将其当作解析器拒绝次数。

## 集成与开销

默认为 `monitoring => false`。仅显式启用的活动会保留有界输入展示和结果计数。
不会添加 RNG 抽取或目标调用。`efz_fuzzer:monitor_snapshot/0` 是版本 1 的只读快照 API：
它返回缓存采样并请求异步刷新。最多存在一个待处理刷新，因此慢目标既不阻塞协调器，
也不产生无限增长的轮询队列。最终采样在活动报告之前发布。
可选预览格式化、函数映射和采样覆盖物化会带来开销；不声称零开销。

## 验证

基于 OTP 27.3.4.1 / Rebar3 3.25.0：

- 默认 EUnit：311 项通过；完整 Gleam/XML-RPC EUnit：377 项通过。
- Common Test：3 项通过；xref 和 Dialyzer 通过。
- 监控集成验证监控关闭与开启时的精确变异配方及覆盖等价性、有界预览、
  一致的最终结果总数，以及目标被故意阻塞时仍可及时响应的快照 API。
- `python3 -m unittest discover -s test -p 'tui_test.py'`：2 项通过，覆盖速率采样与历史边界、
  字节显示及终端控制字符清理。
- 真正的伪终端运行验证了面板渲染、输入固定、窄终端回退、恢复尺寸、退出和重新连接。
  启动演示并关闭查看器后，活动仍继续运行；它完成 10,000 次变异，报告 7/9 探针，
  并可见 `efz_example_parser:classify/1`。

这些检查确认了受支持的单 VM 仪表盘行为，不代表监控性能无损，也不代表支持所有终端模拟器。

## 连续模式

```sh
python3 scripts/tui.py --demo --continuous --out _build/tui-continuous-1
```

此演示没有变异执行次数上限，并把语料条目持久化接纳到 OUTPUT/corpus。
预算显示为 ∞。按 `s` 停止调度新输入，完成当前有界目标执行并保存 report.term。
屏幕保持打开并显示 `stopped_by_user`；`q` 仍只分离查看器，不停止活动。
已连接的监控器也可以请求停止。目标忙碌时，待处理停止和刷新请求会合并。

自定义活动需在可信配置中设置 `max_iterations => infinity`。
若要求语料条目在进程突然终止后仍存在，请设置 `corpus_dir`。
连续 staged 模式保留 RNG、内容游标、工作语料和 Gleam 配置；若未选中 havoc 阶段，会添加它。
普通计划器耗尽一次空闲扫描时，会通过保证大小有界的插入或位翻转产生真正可重放的候选，
而不是只消耗 CPU 的重试循环。连续 staged 活动拒绝零输入上限：唯一的空输入不存在
其他合法变异结果。

单次目标执行超时、判定器预算、运行时验证预算、输入限制、基础设施故障及既有隔离规则
仍然生效。连续报告保留最近 1,024 条解释性决策并记录 `decisions_dropped`，不会丢弃工作
语料或发现分组。轨迹上限保持有界。实际语料增长和不同发现仍消耗存储与内存；
无限执行不代表无限资源。
