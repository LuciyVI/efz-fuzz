## P1 审计决策（2026-10-08）

- 将实际契约 v1 固定为 `{Contract,Model,Codec,Mutator,FeatureSchema,Property}`，全部版本为 1。
  现有变异器和目标 behaviour 加 staged 分发已足够；不添加插件注册表、C ABI 或动态适配器选择。
- 将语料策略称为历史成功提交的 seen，而非活动引用计数。
  只追加条目保留代表。`cover/1` 仅建议子集，不执行裁剪；未来删除必须原子重建一致索引。
- 核心接收操作 ID 或目录索引；EFZ 从显式 exsplus 状态派生操作。
  精确记录普通、成功、回退和错误情况下的下一状态。
- 启动时拒绝延迟判定器。受支持内联属性是纯函数，目标重执行为零；
  未来昂贵判定器需要新的有界执行契约。
- 在分配前检查前置及追加容量，保留现有输出和限制判定。
  因语义不变，版本向量不变。
- Gleam 1.10.0 生成一个未使用 CLI 模块，其引用 stdlib inspection。
  只发布 efz_qs_model，并调整可选 .app 模块列表；在 ebin 外归档旧生成 CLI BEAM。
  保留首次 xref 失败和最终通过的重跑；未引入外部软件包。
- 明确此审查是作者自审。不声称独立审查者、子代理或已完成全部软件包提示词。

- 启动能力错误现明确指出不支持的判定器策略或目标、staged 模式要求、未知选项、
  无效限制、比例或预算。固定有界原子替代不透明 badmatch 结果；成功与关闭行为不变。

## P2 原生集成决策（2026-10-08）

- 保持固定 Gleam 1.10.0、OTP 27.0、Rebar3 3.25.0 和依赖锁不变。
  现有可选 Rebar profile 只使用编译 BEAM 和 .app。
  同一私有工作区两次强制软件包构建产生相同哈希。
- 启用启动时验证全部八个导出核心回调，缺失回调原因有界。
  不增加热路径查找、应用启动或传输。
- 通过比例零、关闭语义反馈和一次纯内联判定器检查证明真实回调。
  追踪顺序为目标、原生快照、适配器、编译 Gleam 解码与检查；不添加生产结构化或引导策略。
- 从源码构建关闭版本，不存在 Gleam 目录、可执行程序或产物。
  固定普通依赖源码的私有副本避免依赖 BEAM 缓存和网络可用性；
  Rebar checkout 覆盖只重写私有锁，不改仓库锁。
- 细粒度采样计数和时间放在有限诊断驱动，独立于生产报告和批量性能测量。
  它不用 RNG。临时 export_all 限于诊断 VM。
- 挂起回调故障注入使用受监视、仅测试的 worker。
  生产层仍采用有界直接调用，不声称任意原生取消或 worker 传输协议。
- 保留初始失败日志：测试桩变量警告、遗漏 scratch 样例源码，以及实际活动使用 collect/1
  时却在 profiled collector 上作出的追踪断言。各问题均已修正，受影响门槛重跑。
- 除版本字符串外，验证实际运行时根目录：初始最小 PATH 关闭构建选择了系统 OTP 27.3.4.13。
  将其保留为额外兼容证据，并在主要 asdf OTP 27.0 上重复全新关闭构建，仍不含 Gleam 或编译器产物。
  记录已安装 P0 覆盖源码的绝对路径。

- 对带标签 semantic_layer_error 原因及通用异常元组都作保护；
  仅 error/exit/throw 类和原子原因可通过。8192 字节带标签故障缩减为 invalid_boundary，保留有限诊断。
