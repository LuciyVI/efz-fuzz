# ADR 0002：使用执行实例拥有的 ETS 实现源代码子句/结果探针

状态：在变换实现前接受，2026-09-08。

基线：OTP 27.0 / ERTS 15.0，x86_64-pc-linux-gnu；Rebar3 3.25.0。
现有七个 EUnit 测试、编译和 Dialyzer 均通过。Common Test
没有测试套件（零个测试）。仓库中不存在格式化器/linter 或 AGENTS.md。
第 1 阶段的大部分实现尚未提交；保留并调整该实现。

## 备选方案

* 抽象形式解析变换：已安装的编译器会在降低表示层级之前公开子句
  主体以及嵌套的 case/if/receive/try/fun 形式。在主体前插入
  调用可保留守卫、模式、求值顺序和尾位置。
  显式表达式遍历和诊断可限制语法风险。
  钩子可以使用执行进程的上下文和外部 ETS 所有者。
* OTP cover 和原生覆盖率：OTP 27 提供原生覆盖率 API（已在
  安装的 code 模块中验证）；cover 会在原生支持可用时使用它。这些
  设施提供行/函数覆盖率和 cover 分析，但其
  面向模块的收集/重置 API 不提供 EFZ 执行引用，
  也不隔离无关进程。适配器还需要额外的隔离
  和归因设计。我们尚未对 cover 进行基准测试，也不声称其速度如何。
* Core Erlang 或 BEAM 重写：降低表示层级会掩盖某些源代码结果，
  并引入与编译器版本的耦合及映射工作。编辑未记录的操作码
  会增加验证风险，却无法解决执行归因问题。

选择一个抽象形式后端。只编译允许列表中的源模块，
并独立于应用程序或模糊测试活动。将清单属性嵌入
BEAM，并在显式编译门面中写出旁车文件。使用 SHA-256 构建
命名空间和确定性的结构探针路径。不编辑源文本。

运行时：每次执行使用一个公开、未命名的 ETS set，由执行器的
监控协调进程拥有，位于目标之外。协调进程还监控
调用者，并在取消时终止并排空目标。只有在目标 DOWN 之后，
它才能对存储进行快照/删除。运行时钩子使用带命名空间的进程字典
上下文；字典不是覆盖率存储。后端错误属于持续生效的
基础设施故障，即使目标异常处理器捕获了这些错误也一样。

模糊测试活动：单个工作进程；校准种子，仅合并成功执行的覆盖率，
保留精确集合新颖性，并单独存储目标崩溃。在
预检时固定构建 ID，并拒绝不兼容的观测结果。仅在显式兼容模式下，
将手动命中 API 保留在单独的身份命名空间中。

使用预热后的重复基准测试，测量普通路径、已插桩但未激活路径和已插桩且激活路径。
ETS 会增加每次命中的工作量；优先保证生命周期正确性，
再考虑优化。在 docs/coverage.md 中记录实际测量结果。

参考资料：[OTP 27 cover](https://www.erlang.org/docs/27/apps/tools/cover.html)
和 [OTP 27 code](https://www.erlang.org/docs/27/apps/kernel/code.html)。
在线 OTP 27 文档描述的是较晚的 27.x 补丁版本；同时还检查了
已安装版本的导出和源码。原生支持在 OTP 27 中加入。
