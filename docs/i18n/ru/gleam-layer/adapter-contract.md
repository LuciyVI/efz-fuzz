# Semantic adapter API 1

[English](../../../gleam-layer/adapter-contract.md) · **Русский** · [Español](../../es/gleam-layer/adapter-contract.md) · [简体中文](../../zh-CN/gleam-layer/adapter-contract.md) · [Все языки](../../README.md)

Контракт зафиксирован до реализации. EFZ владеет исполнением, RNG, планированием,
покрытием, корпусом и replay. Для каждой кампании явно подготавливается ровно один адаптер.
Callbacks исполняются inline в VM EFZ и должны использовать конечные алгоритмы. Перехват исключений
не прерывает цикл; доверенный код плагина обязан соблюдать документированные ограничения.

Обязательные callbacks:

```erlang
descriptor() -> #{id := binary(), api_version := 1, model_version := pos_integer(),
    observer_version := pos_integer(), recipe_version := pos_integer(),
    operations_version := pos_integer(), capabilities := [capability()],
    operations := [non_neg_integer()], model_modules := [module()],
    properties := [{atom() | binary(), pos_integer()}]}.
prepare(Target :: module(), Options :: map(), Limits :: map()) ->
    {ok, ImmutableContext :: term()} | {error, Reason :: term()}.
```

Возможности: `generation`, `mutation`, `observation`, `oracle`, `shrink`.
Callback необходим только для заявленной возможности. Минимальным observer-only и
generator-only плагинам не нужны parser, mutator или oracle. Идентификатор descriptor ограничен
64 байтами; версии — положительные целые. Идентификаторы операций — уникальные целые
0..65535. Модули модели и адаптера исключаются из покрытия цели.
Harness может экспортировать `semantic_contract/0`; плагин проверяет эти метаданные в
prepare/3, а не через центральный список допустимых имён целей. Для runtime-off целей он не нужен.

Необязательные операционные callbacks (обязательны при заявленной возможности):

```erlang
generate(Index :: non_neg_integer(), Context) ->
    {ok, binary()} | {skip, atom()} | {error, term()}.
mutate(Raw :: binary(), Operation :: non_neg_integer(), Params :: map(), Context) ->
    {ok, binary(), RecipeData :: map()} | {skip, atom()} | {error, term()}.
observe(Raw :: binary(), PrimaryOutcome :: term(), Context) ->
    {ok, [LocalFeatureId :: 0..255]} | {skip, atom()} | {error, term()}.
oracle(Raw :: binary(), PrimaryOutcome :: term(), Context) ->
    {pass, Property} | {fail, Property} | {inconclusive, atom()} | {error, term()}.
shrink(Raw :: binary(), Context) ->
    {ok, [binary()]} | {skip, atom()} | {error, term()}.
```

Property — ровно `{Id, Version}` и должен присутствовать в descriptor `properties`.
Observer возвращает список максимум из 64 локальных ID; повторы разрешены и
дедуплицируются диспетчером. Диспетчер добавляет `{AdapterId,
ObserverVersion, LocalId}`; пространства имён не содержат строк, зависящих от входа.
`PrimaryOutcome` — существующий outcome executor EFZ (`{ok, Value}`, timeout,
crash или exit). Адаптеры проверяют и сводят поддерживаемое подмножество перед
вызовом Gleam. Observation и oracle в API 1 никогда не исполняют цель повторно.

Mutation Params — ровно `#{choice => Integer}` (0..65535), выбранное RNG EFZ
и записанное; дополнительные ключи — ошибка границы. Shrink возвращает максимум 64 binary-
кандидата, каждый в пределах действующего ограничения байтов.
Фасад принимает индексы генерации 0..4095. Целые версии — 1..65535;
каталоги операций содержат максимум 256 записей, model_modules/properties — максимум
по 32. Ключи descriptor в точности перечислены выше, capabilities и
ID операций уникальны, а заявленные mutation/oracle требуют непустого
каталога/списка свойств. Defaults: bytes 4096, depth 8, nodes 128, collection
32, operations 1; общие допустимые диапазоны: bytes 0..1048576, depth 1..16,
nodes 1..4096, collection 1..256, operations — ровно 1. Действующее ограничение байтов
также учитывает max_input_bytes кампании.
У адаптеров нет независимого RNG. RecipeData — ограниченные данные, а не исполняемый
код. Новые рецепты записывают identity API/модели/каталога операций, опции/ограничения,
операцию, параметры и состояния RNG EFZ. Обычный raw replay потребляет сохранённые байты
и никогда не загружает плагин. Регенерация рецепта — отдельная явно включаемая операция.

`skip` означает неподдерживаемый формат/размер/ограничение, и мутация использует обычный
байтовый fallback; неизменившая вход мутация тоже вызывает fallback. `inconclusive` означает отсутствие
обоснованного решения oracle. `error` или перехваченное исключение callback — ошибка слоя, никогда не
находка цели. Ожидаемый отказ парсера — outcome цели, а не автоматический
провал oracle. Находку создаёт только явное нарушение поддерживаемого свойства.
Диспетчер проверяет все типы и размеры результатов. Общие ограничения: `bytes`,
`depth`, `nodes`, `collection`, `operations` (одна в API 1); ограничения плагина
проверяются в adapter_options. Контекст callback неизменяем и подготавливается один раз.
Переносимые options/context/RecipeData допускают конечные наборы atoms, ограниченные целые и
конечные float, binary, правильные списки, tuple и map; runtime PID/ref/port/fun
отклоняются. Обход границы допускает глубину максимум 24 и 8192 узла данных,
размер tuple/map максимум 256, отдельный binary максимум 1 MiB.
Закодированные options ограничены 65536 байтами, context — 1 MiB, RecipeData —
4096 байтами, сообщаемые детали ошибки — 1024 байтами. Эти ограничения холодных/граничных данных
отличаются от ограничений представления входа, которые обеспечивает плагин.

Артефакты семантических свойств фиксируют descriptor, BEAM identity адаптера/модели,
действующую конфигурацию, сборки цели/harness и версию свойства. Replay должен
получить явную доверенную конфигурацию адаптера; данные артефакта никогда не выбирают
код. Несовпадение отклоняет replay. Перезапуск корпуса повторно калибрует сохранённые raw bytes
текущими callbacks; сохранённые семантические пространства имён не считаются калибровкой.
Shrinking должен использовать тот же предикат свойства и учитывать каждое исполнение цели;
raw inputs и исходные группы находок остаются неизменными.

Исторические сигнатуры QS-фасада и QS-артефакты schema-1 остаются изолированным
интерфейсом совместимости. Конфигурации без `adapter` принимает только
legacy QS shim. Новые интеграции обязаны явно выбирать адаптер.

Холодный необязательный `code_dependencies(Context) -> #{semantic := [module()], target :=
[module()]}` объявляет максимум 32 модуля каждой категории. EFZ фиксирует их код существующим
механизмом BEAM identity. Семантические helpers/свойства исключаются из
покрытия цели; объявленные зависимости цели могут выбираться для покрытия. Этот
callback делает динамически заданные свойства и API воспроизводимо идентифицируемыми
без знания диспетчером имён опций. Отсутствие callback означает отсутствие дополнительных модулей.
Постоянная identity хранит действующие опции адаптера как непрозрачные несжатые ETF bytes;
raw replay никогда не декодирует опции и не интернирует atoms плагина. Имена модулей/свойств descriptor —
переносимые binary. Semantic replay сравнивает с заново подготовленной доверенной конфигурацией
вызывающей стороны. Та же identity фиксирует SHA-256 детерминированного переносимого
подготовленного контекста (закодированный context максимум 1 MiB).
Изменение холодного контекста не может незаметно изменить записанный предикат replay.
prepare/3 должен воспроизводиться из объявленных target/options/environment;
невоспроизводимая внешняя конфигурация даёт явное несовпадение identity.

Новый structured provenance хранит callback RecipeData как непрозрачные детерминированные ETF
bytes (максимум 4096), исключая atoms адаптера из raw-декодирования рецепта.
Регенерация рецепта schema-4 использует сохранённые байты замены; отдельный
явный API регенерации требует совместимой доверенной конфигурации адаптера.
