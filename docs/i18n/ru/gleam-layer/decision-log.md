# Решения

[English](../../../gleam-layer/decision-log.md) · **Русский** · [Español](../../es/gleam-layer/decision-log.md) · [简体中文](../../zh-CN/gleam-layer/decision-log.md) · [Все языки](../../README.md)

1. Использовать установленный Gleam 1.10.0 из /tmp/efz-gleam-toolchain/gleam после фактической
   проверки сборки/BEAM; закрепить точную версию. Не обновлять автоматически до latest.
2. Использовать закреплённый query-string parser Cowlib без его переписывания. Модель содержит
   binary ключи/значения, упорядоченные дубликаты и намеренно некорректный escape.
3. Сохранить существующие нативное покрытие и изоляцию guardian. Публичные счётчики OTP
   имеют область модуля; чистый inline oracle не делает дополнительных вызовов цели.
4. Необязательный post_compile hook использует ebin результата export erlang-shipment,
   не предполагая наличие сгенерированного .erl. Пакет stdlib или внешний runtime не нужен.
5. Точные конечные признаки корпуса учитываются только после устойчивого допуска.
   Аннотации существующих seeds перестраиваются обычной калибровкой после restart. Нет
   скрытой кампании, планировщика, semantic ETS-таблицы, очереди, кэша или worker.
6. Записывать structured_replace как data-only операцию v2. Новая structured recipe
   schema 3 добавляет проверяемый RNG provenance; прежние schemas 1/2 воспроизводятся при off.
7. Нарушения oracle используют существующие неизменяемые crash groups независимо от
   допуска в корпус. Sidecar .semantic с контрольной суммой требует manifest v2 (максимум пять
   файлов); обычные находки сохраняют manifest v1. Семантические discoveries корпуса используют
   schema v3; старые v1/v2 записи корпуса принимаются. Несовпадение schema — ошибка.
8. Сохранять последних семантических представителей при консервативном cover-сокращении.
   Существующий корпус append-only; online pruning policy не добавляется.
9. Исправить существующий конфликт вложенного каталога тестовых исходников, переместив четыре
   неизменённых harness в examples и обновив ссылки на исходники. Сохранить все
   исходные generated test artifacts в _build/test-before-gleam-layout.
10. Полные регрессии обнаружили отсутствие zero-budget guard в выделенной функции ordinary
    attempts; восстановить его и повторить тесты планировщика. Повторяемые fixture-
    каталоги теперь используют уникальные timestamps против коллизий старых сборок.

Проверены исходники: установленный OTP 27 kernel code.erl и закреплённые cow_qs/cow_inline.
Первичные онлайн-источники: https://gleam.run/documentation/externals/,
https://www.erlang.org/doc/apps/kernel/code.html,
https://gleam.run/news/gleam-doesnt-compile-to-erlang-source-anymore/.
Текущая онлайн-документация/релизы не определяют артефакты закреплённого компилятора;
доказательства дают вывод Gleam 1.10.0 и реальные BEAM-вызовы.

## Решения аудита P1 (2026-10-08)

- Зафиксировать фактический контракт v1 как `{Contract,Model,Codec,Mutator,FeatureSchema,Property}`,
  все версии 1. Достаточны существующие behaviour mutator/target и staged-диспетчеризация;
  не добавлять реестр плагинов, C ABI или динамический выбор адаптера.
- Называть политику корпуса историческим множеством успешно зафиксированных seen, а не active refcounts.
  Append-only entries сохраняют представителей. `cover/1` предлагает подмножество, но не
  применяет pruning; будущее удаление должно атомарно перестраивать согласованные индексы.
- Ядро получает ID операции/индекс каталога; EFZ выводит операции из явного
  состояния exsplus. Точно описать следующее состояние для ordinary/success/fallback/error.
- Отклонять deferred oracle при старте. Поддерживаемое inline-свойство чистое и
  не исполняет цель повторно; будущему дорогому oracle нужен новый ограниченный
  контракт исполнения.
- Проверять ёмкость prepend/append до выделения памяти, сохраняя существующие результаты
  и limit-вердикты. Вектор версий не менять, поскольку семантика не меняется.
- Gleam 1.10.0 генерирует неиспользуемый CLI-модуль со ссылкой на stdlib inspection.
  Поставлять только efz_qs_model и соответственно исправить modules необязательного .app; архивировать старый
  generated CLI BEAM вне ebin. Первая ошибка xref и финальный успешный повтор
  сохранены; внешний пакет не вводился.
- Review явно является самопроверкой автора. Независимый reviewer/субагенты и
  завершение каждого prompt пакета не заявляются.

- Ошибки возможностей при старте теперь явно называют неподдерживаемые oracle policy/target,
  требование staged-режима, неизвестные опции, неверные limits/fraction/budget. Фиксированные
  ограниченные atoms заменяют непрозрачные badmatch; успешное/off поведение сохранено.

## Решения нативной интеграции P2 (2026-10-08)

- Сохранить закреплённые Gleam 1.10.0, OTP 27.0, Rebar3 3.25.0 и неизменные lock-файлы
  зависимостей. Существующий opt-in профиль Rebar потребляет только скомпилированные BEAM и .app.
  Две принудительные сборки пакета в одном частном workspace дают одинаковые хеши.
- Проверять все восемь экспортированных callbacks ядра при включённом старте с ограниченной
  причиной missing-callback. Никаких hot-path lookup, старта application или транспорта.
- Доказать реальный callback с fraction zero, отключённым semantic feedback и
  одной чистой inline oracle-проверкой. Trace упорядочивает target, native snapshot, adapter,
  compiled Gleam decode/check; production structured/guidance policy не добавляется.
- Выполнить off-сборку из исходников без каталога/исполняемого файла/артефактов Gleam. Частные
  копии закреплённых обычных исходников зависимостей исключают опору на BEAM-кэши
  или доступность сети; checkout override Rebar переписывает только
  частный lock, оставляя lock репозитория неизменным.
- Держать детальные выборочные счётчики/времена в конечном диагностическом драйвере
  отдельно от production-отчётов и пакетных измерений производительности. Он не использует
  RNG. Временный export_all ограничен диагностической VM.
- Инъекция зависающего callback использует monitored test-only worker.
  Production-слой сохраняет ограниченные прямые вызовы; произвольная native-отмена
  и транспортные протоколы worker не заявляются.
- Сохранить первоначальные неуспешные логи: предупреждение переменной в test stub; пропущенные scratch-
  исходники fixture; trace-assertion на profiled collector, тогда как
  фактическая кампания использовала collect/1. Каждая проблема исправлена, затронутая проверка повторена.
- Проверять фактические runtime roots вместе со строками версий: первоначальный minimal-PATH
  off выбрал системный OTP 27.3.4.13. Сохранить это как дополнительное доказательство совместимости
  и повторить чистый off на основном asdf OTP 27.0, по-прежнему без Gleam/compiler
  artifacts. Записать абсолютный путь установленного исходника покрытия P0.

- Ограничивать tagged-причины semantic_layer_error вместе с общими exception tuples;
  пропускать только классы error/exit/throw с атомарными причинами. Tagged-сбой в 8192 байта
  сводится к invalid_boundary, сохраняя конечность диагностики.

## Решения provider P3 (2026-10-08)

- Сохранить выбор parent/lane, mutation budget, корпус и исполнение цели EFZ.
  Декодировать только после структурного выбора; fallback напрямую один раз вызывает ordinary_attempts
  с состоянием RNG после выбора. Ошибки останавливают работу с диагностикой.
- Сохранить семантику шести операций/model/codec/mutator v1. Заменить отброшенное
  кодирование мутатора preflight-проверкой размера; сравнить результаты с архивированным
  P2 BEAM в отдельной диагностической VM. Кэш, обучаемые подсказки и worker не добавляются.
- Расширить только холодный каталог до версии 2 (пакет 1.1.0). Двенадцать разных
  слотов покрывают границы component/field/wire; подготовка остаётся отдельной,
  все входы поступают в существующие CLI/корпус как raw bytes.
- Новая structured recipe schema 3 сохраняет точные proper-list слова состояния exsplus,
  ограничения и fraction; ordinary-рецепты сохраняют schema 1, а прежняя structured schema
  2 остаётся читаемой. Operation v2 и EFZR envelope v1 не меняются.
- Детальные компонентные замеры остаются ограниченным диагностическим драйвером; счётчики кампании
  добавляют количества операций и generated bytes. Доли 1/5/10/20 —
  исследовательские замеры одного движка, а не оптимум или преимущество производительности.

## Решения feedback P4 (2026-10-08)

- Сохранить query_model_agreement v1: сравнивать независимо декодированные поддерживаемые query-
  поля с завершённым результатом настоящего парсера Cowlib. Это expected-result
  свойство, не differential-проверка и не round-trip закон слоя. Повтор цели
  или дорогой/deferred online oracle не добавляется.
- Сохранить точное пространство cow_qs/1 с 12 ID и максимум четырьмя на исполнение. Требовать
  канонические точно сформированные сохранённые метаданные. Read-only холодный
  запрос корпуса выводит один representative ID на признак без постоянного индекса.
- Фиксировать новые raw bytes/метаданные до semantic seen существующим сериализованным
  владельцем корпуса. Параллельные дубликаты признаков получают одно зачисление; повтор после
  неудачной записи сохраняет новизну. Аннотации существующих входов перестраиваются после restart.
- Append-only онлайн-корпус не требует транзакции удаления/refcount. Проверять
  консервативное cover-подмножество копированием в новый store и повторной калибровкой;
  сохранять исходные артефакты и отклонять schema mismatch. Ручное удаление между
  кампаниями не оставляет устаревший глобальный seen-индекс; онлайн-редактирование диска не поддерживается.
- Проверять зафиксированные native bits и непустые декодированные units. Начальный trace-
  assertion ошибочно сравнивал пустые diagnostic coverage lists; сохранить прежние
  доказательства и заменить acceptance evidence исправленным native-доказательством.
- Сохранить нормальное продолжение после находки и существующую политику fingerprint/representative.
  Подключение искусственного дефекта — не реальная находка Cowlib и не discovery-эксперимент.
  Вызовы replay/минимизации считаются отдельно; production oracle добавляет ноль.
