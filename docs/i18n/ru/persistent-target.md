# Постоянная VM тестируемой цели

Это краткое руководство. [Полный lifecycle, журнал и replay](../../persistent-target.md) опубликованы на английском.

`execution.mode = persistent_vm` и `state_policy = accumulate` включаются явно. Внутри эпохи сохраняются VM и PID драйвера цели, process dictionary, mailbox и принадлежащие цели OTP/ETS ресурсы. Для каждого input открывается новое окно покрытия; оно не является разностью накопленного union. Crash, timeout или потеря integrity завершают эпоху, а новый запуск образует новую эпоху.

Журнал записывает точные байты и порядок входов до отправки цели. Sequence replay проходит от `init` через весь prefix; одиночный raw replay не восстанавливает историю. Независимые повторы одной последовательности выполняются последовательно в новых эпохах, не вмешиваясь в primary trajectory. У произвольной фоновой активности без barrier полнота окна не гарантирована.
