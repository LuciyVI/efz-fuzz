# Обвязки Cowboy для проверки потоков данных

[English](../../cowboy-harness-suite.md) · **Русский** · [Español](../es/cowboy-harness-suite.md) · [简体中文](../zh-CN/cowboy-harness-suite.md) · [All languages](../README.md)

Этот набор проверяет EFZ с закреплёнными версиями зависимостей Cowboy 2.19.0 и
Cowlib 2.20.0. Одиннадцать отдельных целей воспроизводят реальные потоки данных
библиотек. Один и тот же код целей, начальный корпус, начальные значения ГПСЧ и
бюджет мутаций используются при отключённом необязательном слое Gleam, при его
работе в режиме наблюдения или при управлении мутациями и сохранением входов.

Входы — это **байты полезных данных**, до 1024 байт. Обвязки конструируют
корректные сообщения вокруг этих данных и проверяют результат работы библиотеки.
Там, где это предусмотрено, байт-селектор выбирает документированный вариант.
Каждый вход в пределах бюджета достигает кода библиотеки; предварительной
оболочки кодирования термов, которая могла бы его отклонить, нет. Набор проверяет
успешный разбор и доставку данных и не считает обычное отклонение входа дефектом.

## Входные поверхности и реализованные пути

Каждое имя выбирает `efz_cowboy_<name>_target:run/1`. Реализации используют общий
файл [`efz_cowboy_flow.erl`](../../../examples/cowboy/targets/efz_cowboy_flow.erl);
отдельные точки входа позволяют независимо учитывать покрытие и корпус.

| Имя | Входная поверхность и фактический поток данных | Проверяемый контракт | Границы проверки |
| --- | --- | --- | --- |
| `qs` | Полезные данные → `cow_qs:urlencode/1` → `cowboy_req:parse_qs/1` → `match_qs/2` | Декодированная пара и сопоставленное поле равны исходным байтам, включая нулевые байты и байты вне UTF-8 | Одно именованное поле; корректные escape-последовательности, сформированные обвязкой |
| `headers` | Селектор/полезные данные → корректное значение → `cowboy_req:header/2`, `parse_header/2` → парсер Cowlib | Получение заголовка сохраняет значение; длина содержимого равна длине полезных данных | Шесть семейств заголовков: content length, content type, range, Basic authorization, accept encoding, connection |
| `cookies` | Полезные данные → значение cookie в шестнадцатеричном виде → `parse_cookies/1` → `match_cookies/2` → `filter_cookies/2` → повторный разбор | Значение сохраняется при сопоставлении; фильтрация удаляет другую cookie | Две корректные cookie; произвольная грамматика cookie не проверяется |
| `router` | Селектор/полезные данные → путь запроса → `cowboy_router:execute/2` → преобразование с учётом ограничений → `cowboy_req:binding/2` или `path_info/1` | Выбранный маршрут, целочисленная привязка и хвост пути соответствуют построенному запросу | Доверенная фиксированная таблица маршрутизации: корень, ID элемента с ограничением, путь к файлу с подстановкой; обработчик не выполняется |
| `http1` | Сформированный запрос → настоящий `cowboy_http:init/6` → существующий транспорт Ranch в памяти → обработчик потока → маршрутизатор, QS, доставка тела | Длина доставленного тела равна исходной длине при обрамлении content-length/chunked; равна нулю для варианта без тела | Один полный запрос/соединение; существующий синхронный приёмник потока, без сокета |
| `http2` | Полезные данные → `cow_http2:data/3` → `cow_http2:parse/1` | ID потока DATA, флаг FIN, полезные данные и пустой остаток совпадают с ожидаемыми | Цикл кодирования и декодирования кадра Cowlib, не соединение Cowboy HTTP/2 |
| `http3` | Полезные данные → `cow_http3:data/1` → `cow_http3:parse/1` | Полезные данные DATA и пустой остаток совпадают с ожидаемыми | Цикл кодирования и декодирования кадра Cowlib, не QUIC и не соединение Cowboy HTTP/3 |
| `websocket` | Селектор/полезные данные → кадр text/binary/ping → `cow_ws:frame/2` → `parse_header/3` → `parse_payload/9` | Декодированные полезные данные и пустой остаток совпадают с ожидаемыми | Полные немаскированные кадры, без фрагментации и сжатия; ping ограничен 125 байтами |
| `multipart` | Полезные данные → поле формы в шестнадцатеричном виде с фиксированным разделителем → `cow_multipart:parse_headers/2` → `parse_body/2` → разбор конечного разделителя и content-disposition | Тело, имя поля и конечный разделитель совпадают с ожидаемыми | Одна полная часть; без жизненного цикла потокового `read_part` в Cowboy |
| `hpack` | Полезные данные → список заголовков → `cow_hpack:encode/3` → `decode/3` → второй блок с использованием тех же локальных таблиц | Оба декодированных списка заголовков равны исходному | Новые таблицы размером 512 байт при каждом выполнении, два блока, не более 16 декодированных заголовков |
| `qpack` | Полезные данные → список заголовков → `cow_qpack:encode_field_section/4` → `decode_field_section/3` | Список заголовков совпадает с исходным; при нулевой ёмкости таблицы инструкции кодировщика отсутствуют | Статические/литеральные секции полей; без динамической таблицы, блокирования потоков или управляющих потоков QUIC |

Этот перечень отделяет реализованные пути библиотек от более широких
сценариев развёртывания. Сокеты TLS/Ranch, планирование соединений, автоматы
состояний соединений HTTP/2 и HTTP/3, QUIC/WebTransport, сжатые сообщения
WebSocket, потоковый multipart и специфичное для приложения поведение
REST/статических ресурсов/обработчиков требуют собственных фикстур жизненного
цикла. Набор не заявляет покрытие этих путей.

Существующий бенчмарк с сырыми входами HTTP/1 описан отдельно в
[`cowboy-long-benchmark.md`](cowboy-long-benchmark.md). Его корпус данных в
сетевом формате отличается от используемого здесь корпуса полезных данных.

## Запуск без Gleam

Из корня репозитория с Erlang/OTP 27 или новее:

```sh
export ERL_FLAGS='+S 2:2'
rebar3 compile
escript scripts/cowboy_suite.escript --surface all --mode off \
  --iterations 500 --seed 424242 --out _build/cowboy-flows-off
```

Обычному профилю не нужны компилятор Gleam или сгенерированные BEAM-файлы модели.
Выходные каталоги должны быть новыми. Каждая поверхность запускается в новой VM
со своим корпусом и артефактами нативного покрытия строк только целевого кода.

## Запуск всех трёх режимов

```sh
export ERL_FLAGS='+S 2:2'
export GLEAM_BIN=/path/to/gleam-1.10.0
rebar3 as gleam compile
escript scripts/cowboy_suite.escript --surface all --mode all --profile gleam \
  --iterations 500 --seed 424242 --out _build/cowboy-flows-three-modes
```

Для запуска одного пути используйте, например, `--surface http1`. Режимы:

| Режим | Доля структурированных мутаций | Приём в корпус | Необязательная модель |
| --- | --- | --- | --- |
| `off` | 0% | Структурное покрытие | Нет |
| `observation_only` | 0% | Структурное покрытие; наблюдения записываются | Скомпилированная модель Gleam `efz_term_model` |
| `guided` | 30% | Структурное покрытие или новые семантические признаки | Та же модель и `efz_cowboy_flow_adapter` |

Режим наблюдения сохраняет базовую последовательность мутаций и потребление
значений ГПСЧ. Управляемый режим намеренно меняет выбранные мутации, а вслед за
ними и корпус. Общий адаптер наблюдает фактические результаты с помощью
существующей модели термов Gleam, а также признаков предметной области с
конечными множествами значений, таких как размер доставленного тела, маршрут,
семейство заголовка и диапазон длины значения. Структурированные операции меняют
селектор, расширяют полезные данные или генерируют полезные данные граничного
размера в установленных пределах.
Отдельной реализации разбора Cowboy на Gleam нет.

Проверки внутри обвязки выполняются в **каждом** режиме. Они проверяют
согласованность цикла кодирования/декодирования и доставки данных, а не полное
соответствие RFC. Оракул семантического слоя отключён, поэтому новый семантический
признак не считается семантической находкой. Неожиданные исключения передаются
EFZ и требуют исследования; они не считаются автоматически подтверждёнными
дефектами библиотеки. Известные дефекты или эксплойты не используются.

## Чтение результатов

Каждый каталог `<surface>/<mode>/` содержит:

- `initial-corpus/`, `config.term` и `identity.term`: точные входы, настройки
  ГПСЧ, версии приложений и идентификаторы сборок целей.
- `target-beams/` и `artifacts.term`: сборки для нативного покрытия только
  целевого кода. Код обвязки, адаптера, наблюдателя и EFZ исключён из списка
  измеряемых модулей.
- `report.term`, `snapshot.term`, `summary.term`: результат кампании, покрытие,
  корпус, временные показатели, семантическая/структурированная статистика и
  число вызовов библиотек.
- `corpus/` и `crashes/`: сохраняемые артефакты EFZ для обычных сценариев
  повторного воспроизведения.

Файл `summary.csv` в корневом каталоге результатов сравнивает поверхности и
режимы. `comparisons.csv` записывает накладные расходы по времени относительно
соответствующего запуска `off`. Одна парная кампания — лишь пробное измерение;
она не доказывает преимущества в скорости или обнаружении дефектов. Временные
показатели управляемого режима включают другую входную нагрузку.

`target_invocations` и `target_accepted` включают калибровку и мутации. Исполнитель
сверяет учёт вызовов с бюджетом выполнений. При запуске без ошибок каждый вызов
должен успешно выполнить контракт библиотеки. `discoveries` и
`corpus_equivalent_rejections` описывают приём в корпус, а не успех или отклонение
на уровне API. Покрытие, полученное при калибровке, отражается отдельно от
`mutation_new_coverage_lines`, чтобы начальный корпус нельзя было принять за
прогресс мутаций. Знаменатель при расчёте покрытия включает выбранные модули
целиком, в том числе функции, недостижимые в выбранном потоке данных; он не
представляет максимум для достижимых путей.

`report.etf` сохраняет полный бинарный отчёт. В текстовых отчётах ссылки и другие
идентификаторы среды исполнения представлены помеченными значениями: их можно
прочитать через `file:consult/1`, сохранив байты бинарных входов.

## Регрессионные проверки

```sh
rebar3 eunit --module=efz_cowboy_flow_tests,efz_cowboy_long_tests
GLEAM_BIN=/path/to/gleam-1.10.0 rebar3 as gleam eunit --module=efz_cowboy_flow_tests
```

Локальная проверка завершила 33 кампании по 500 мутаций: 16 500 мутаций и 264
калибровки, все 16 764 вызова библиотеки приняты, без исключений, тайм-аутов и
инфраструктурных сбоев. Сохранённые входы, покрытие и статистика мутаций совпали
между off и observation-only для всех одиннадцати поверхностей. HTTP/1 достиг
313 строк и 26 элементов корпуса без слоя, против 312 строк и 32 элементов с
guided: дополнительные сохранения не доказывают улучшения покрытия.
См. общие [CSV-результаты](../../cowboy-harness-suite-validation/summary.csv),
[идентификаторы сборок](../../cowboy-harness-suite-validation/identities.term) и
[манифест воспроизведения](../../cowboy-harness-suite-validation/manifest.json).
Параллельно выполнялись другие локальные проверки, поэтому эти замеры времени
не выделяют накладные расходы слоя. Полные отчёты кампаний остались в локальном
дереве `_build`; манифест содержит их хеши и точную команду воспроизведения.

Тесты проверяют пустые входы, двоичные входы и входы максимального размера для
всех одиннадцати путей, воспроизводимость структурированных мутаций и уменьшения
входов, одинаковые настройки кампаний, доставку тела и очистку транспорта HTTP/1
в памяти. Необязательная сборка также проверяет, что различные результаты
библиотеки порождают различные семантические признаки.
